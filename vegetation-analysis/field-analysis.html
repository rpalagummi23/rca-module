PlanetScope Field-Level Vegetation Analysis

From raw GeoTIFF pixels to field-level NDVI — a complete calculation walkthrough using a 0.63 ha rice field in Chhattisgarh, India

1. The Input: PlanetScope 8-Band GeoTIFF

PlanetScope SuperDove satellites capture 8 spectral bands per pixel at 3-meter ground resolution. Each GeoTIFF is a 3D raster array with shape [bands, height, width].

BandNameCenter WavelengthUse
B1Coastal Blue431 nmAtmospheric correction
B2Blue465 nmEVI denominator, water
B3Green I513 nmVegetation greenness
B4Green547 nmChlorophyll absorption
B5Yellow610 nmSenescence detection
B6Red665 nmNDVI, EVI, SAVI
B7Red Edge717 nmNDRE, CI_RedEdge
B8NIR865 nmAll vegetation indices
Scale factor: PlanetScope Surface Reflectance (SR) values are stored as integers scaled by 10,000. A raw pixel value of 2996 in the NIR band means a reflectance of 0.2996.

3. Pixel Extraction from GeoTIFF

3.1 What is a "row" of data?

Each pixel in the GeoTIFF becomes one row of data. A pixel is identified by its (row, col) position in the raster grid and its geographic coordinates (x, y). Each row contains all 8 band values.

3.2 Clipped vs Unclipped

The GeoTIFF may cover a much larger area than your field. When you clip the raster to the KML polygon, only pixels inside the field boundary are extracted.

ScenarioPixel CountExplanation
Full composite.tif (unclipped)1,041,4111146 × 915 grid minus NoData pixels. Covers ~930 ha.
Clipped to 0.63 ha KML field~700Only pixels whose centers fall inside the polygon.

3.3 NoData and Cloud Masking

Two types of invalid pixels are excluded:

  • NoData pixels — All 8 bands equal zero. These are outside the satellite's imaging swath.
  • Cloud/shadow pixels — Identified by the UDM2 mask (8-band quality mask). A pixel is "clean" when: clear=1 AND cloud=0 AND shadow=0 AND haze=0

3.4 Extraction Output

For each valid pixel, one row is written with 17 columns:

pixel_row, pixel_col, x, y, date, B1_CoastalBlue, B2_Blue, B3_GreenI,
B4_Green, B5_Yellow, B6_Red, B7_RedEdge, B8_NIR,
NDVI, NDRE, EVI, SAVI, CI_RedEdge

4. Vegetation Index Formulas (Computed Per Pixel)

Every index is calculated independently for each pixel row using that pixel's band values. There is no averaging at this stage.

NDVI — Normalized Difference Vegetation Index

NDVI = (NIR - Red) / (NIR + Red)

Primary vegetation greenness indicator. Range: -1 to +1. Healthy vegetation: 0.6–0.9.

NDRE — Normalized Difference Red Edge

NDRE = (NIR - RedEdge) / (NIR + RedEdge)

Sensitive to chlorophyll content in dense canopy where NDVI saturates. Range: -1 to +1. Healthy: 0.3–0.7.

EVI — Enhanced Vegetation Index

EVI = 2.5 × (NIR - Red) / (NIR + 6 × Red - 7.5 × Blue + 1)

Corrects for atmospheric and soil background effects. More linear than NDVI in dense canopy. Range: -1 to +1.

SAVI — Soil-Adjusted Vegetation Index

SAVI = ((NIR - Red) / (NIR + Red + 0.5)) × 1.5

Reduces soil brightness influence in sparse canopy. L factor = 0.5 (standard). Range: -1.5 to +1.5.

CI_RedEdge — Chlorophyll Index Red Edge

CI_RedEdge = (NIR / RedEdge) - 1

Linear estimator of leaf chlorophyll content. No upper bound; typical healthy vegetation: 1–5.

Epsilon: A small constant (1×10-10) is added to denominators to avoid division by zero on bare soil or water pixels.

8. Level 2 — Per-Pixel Temporal Summary (pixel_phenology.csv)

8.1 Why group by pixel?

Each pixel represents a fixed 3m × 3m patch of ground. By grouping all 40 observations of the same pixel across time, you get that pixel's individual growth curve. This preserves spatial variability — different parts of the field may behave differently.

8.2 The grouping operation

# Group all 40M rows by pixel identity
grouped = pixel_df.groupby(['pixel_row', 'pixel_col'])

# For each pixel, we now have a time-series of ~40 NDVI values
for (row, col), pixel_group in grouped:
    ndvi_timeseries = pixel_group['NDVI'].values  # shape: (40,)
    dates = pixel_group['date'].values            # shape: (40,)

8.3 Per-pixel smoothing

Raw NDVI values are noisy due to atmospheric effects, sub-pixel clouds, and sensor variability. For each pixel's time-series, a Savitzky-Golay filter is applied to produce a smooth growth curve.

# Smooth each pixel's NDVI time-series independently
ndvi_smooth = savgol_filter(ndvi_timeseries, window_length=7, polyorder=2)

8.4 Peak detection and heading date

For each pixel's smoothed curve:

  1. Peak NDVI — the maximum of the smoothed curve. This corresponds to peak canopy/vegetative stage.
  2. Heading date — detected by first-derivative zero-crossing after the peak. The point where NDVI stops rising and starts declining marks the transition from vegetative to reproductive stage.
# First derivative of smoothed NDVI
deriv = np.gradient(ndvi_smooth)

# Find where derivative crosses zero after peak (rising → declining)
for j in range(peak_idx, n_obs - 1):
    if deriv[j] > 0 and deriv[j + 1] <= 0:
        heading_date = dates[j]
        break

9. Level 3 — Field-Level Summary (field_summary.csv)

9.1 How field NDVI is calculated

This is the answer to: "What is the NDVI for my whole 0.63 ha KML field?"

For each date, all ~700 pixel NDVI values within the field polygon are aggregated:

# For each date, aggregate all pixels in the field
for date, group in pixel_df.groupby('date'):
    ndvi_values = group['NDVI'].values  # ~700 values

    record = {
        'date': date,
        'n_pixels': len(ndvi_values),
        'NDVI_mean': np.mean(ndvi_values),     # ← Field-level NDVI
        'NDVI_std':  np.std(ndvi_values),      # Spatial variability
        'NDVI_p10': np.percentile(ndvi_values, 10),  # Worst 10%
        'NDVI_p50': np.percentile(ndvi_values, 50),  # Median
        'NDVI_p90': np.percentile(ndvi_values, 90),  # Best 10%
    }

11. Why Not Just Average Immediately?

The original notebook (cell 35) collapsed all pixel values to a field mean immediately after extraction:

# Original approach (notebook cell 35) — loses per-pixel identity
for name, arr in idx.items():
    valid = arr[clean_mask]
    record[f"{name}_mean"] = np.nanmean(valid)  # ← 700 pixels → 1 number

This works for a quick overview but loses critical information:

What You LoseWhy It Matters
Spatial variability within the fieldOne corner may be stressed while the rest is healthy
Per-pixel heading dateDifferent parts of the field may flower on different days
Outlier detectionA few dead pixels can pull the mean down without being identified
Per-pixel growth stage classificationCannot map which parts are vegetative vs reproductive
Stress localizationCannot identify where in the field a problem occurs
The fix: Preserve per-pixel identity through the entire pipeline. Only aggregate to field level as the last step, after per-pixel temporal analysis is complete.

14. Practical Example: Reading the Outputs

14.1 "What is the NDVI of my field on June 15?"

Open field_summary.csv, find the row where date = 2024-06-15, read NDVI_mean.

14.2 "Is the northwest corner of my field stressed?"

Open pixel_timeseries.csv, filter by the (x, y) coordinates of the northwest corner, compare NDVI values to the field mean.

14.3 "When did each part of my field reach peak NDVI?"

Open pixel_phenology.csv, look at the peak_ndvi_date column. Map it spatially by (pixel_row, pixel_col) to see which parts peaked early vs late.

14.4 "What is the overall season NDVI for my field?"

From field_summary.csv, take the maximum NDVI_mean across all dates (peak canopy NDVI), or compute the mean of all NDVI_mean values (season average).

15. Field Phenology Summary (field_phenology.csv)

This is the missing link between per-pixel phenology and farmer-facing advisories. It aggregates pixel_phenology.csv into a single row summarizing the entire field's season.

15.1 How it's computed

The field-level phenology is derived two ways and cross-checked:

  1. From field_summary.csv — Smooth the field-mean NDVI time-series (40 values), detect peak and heading date on the smoothed curve.
  2. From pixel_phenology.csv — Average all pixels' heading dates, peak NDVI, stress flags to get field-level consensus.

16. Farmer Advisory & Yield Estimation TBD

The following sections describe what is needed to go from satellite-derived phenology to actionable farmer advisories and yield estimates. These are not yet implemented in the pipeline.

16.1 Field Phenology (from existing pipeline)

The field_phenology.csv provides the foundation:

  • Smooth field_summary.csv's NDVI_mean time-series (Savitzky-Golay)
  • Detect peak NDVI date → heading date
  • Detect season start (NDVI crosses 0.2 rising) → transplanting date
  • Detect season end (NDVI drops below 0.2) → harvest readiness
  • Measure peak NDVI value → canopy vigor

16.2 Yield Estimation Requires Ground Truth

NDVI alone does not give yield — you need a calibration model. Three options:

Option A: Empirical Regression

Collect actual yield data (kg/ha) from 50–100 fields over 2–3 seasons. Regress yield against peak NDVI, cumulative NDVI (sum across season), or NDVI at heading. Typical R² = 0.5–0.7 for rice.

Yield (kg/ha) = β0 + β1 × Peak_NDVI + β2 × Cumulative_NDVI

Option B: Crop Simulation Model

Feed NDVI-derived phenology dates (transplanting, heading, maturity) into a crop model like DSSAT or ORYZA. The model estimates yield based on weather + phenology. Requires daily weather data (temperature, rainfall, solar radiation).

Option C: ML Model

Train on historical satellite indices + weather + soil + actual yield. Needs labeled data from multiple seasons. Can use Random Forest, XGBoost, or LSTM for time-series features.

Without ground-truth yield data, you cannot estimate yield. Satellite indices only correlate with yield — they don't measure it directly.
