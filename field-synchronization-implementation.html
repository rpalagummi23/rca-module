field_synchronization.py

Implementation, design rationale, deployment, and testing for the Temporal Flowering Synchronization Score (FSS) — the companion to the PlanetScope Field-Level Vegetation Analysis pipeline

Where this fits: field-analysis.html documents the upstream pipeline (GeoTIFF → pixels → indices → field-mean curves). This document covers the downstream synchronization module only. It assumes the indices already exist and starts from a field-mean-per-date table.

1. Scope & Assumptions

AspectDecision
Input granularityField-mean per date — one row per scene date with already-computed indices. No raster / per-pixel work.
Indices consumedNDVI (required); NDRE and CI_RedEdge (optional but recommended)
GDD / weather / sowing datesNot available — the FSRI "heading deviation" term is intentionally omitted; heading timing is derived from the satellite curve itself
What it measuresTemporal flowering synchronization of the whole field: a sharp, narrow, smooth flowering peak → synchronized; a broad, flat, or jagged peak → staggered / desynchronized
OutputsA single summary row (printed report + optional one-row CSV). No plots.
Season shape handledIrregular sampling (e.g. ~80 clear scenes out of ~110 days)
Honest limitation: With field-mean-only data, this score cannot measure spatial uniformity (which corner lagged) or true male/female-row synchronization — those need per-pixel data and weather/sowing records. At PlanetScope's 3 m resolution the male/female rows (40–60 cm) are sub-pixel and already averaged together. This is a temporal proxy, validated directionally but not against ground-truth seed-set data.

2. The FSS Formula

FSS = w₁·PeakBroadness + w₂·CurveRoughness + w₃·VigorAsymmetry + w₄·StressFlag

Each component is normalized to 0–1 (0 = perfectly synchronized, 1 = worst). Default weights: 0.35 / 0.25 / 0.20 / 0.20. The composite range is 0–1; lower is better.

PeakBroadness Did the field bloom in one tight burst, or a drawn-out plateau? Count days where smoothed NDVI ≥ 95% of peak (flowering duration); compare to an ideal 5-day burst:
clip((duration − 5) / 20, 0, 1)		 rice-flowering-sync.html ("sharp narrow peak = synchronized")
CurveRoughness Jagged / oscillating growth indicates rows at different stages RMSE of the raw−smoothed NDVI residual over the booting→heading run-up (last ~20 days), normalized by 0.04 docx Method 1 (temporal slope/variance)
VigorAsymmetry Was the canopy at full vigor when it headed? 1 − NDRE_at_heading / NDRE_season_max (season-max NDRE used as the "expected healthy" proxy) FSRI component 2
StressFlag A sudden dip (cold snap, heavy rain, missed cloud) during flowering Worst negative raw−trend residual within ±7 days of heading, as a fraction of NDVI at heading FSRI component 3

Supporting Phenology Markers (reported for free)

  • Heading date — date of maximum smoothed NDVI
  • Booting date — date of maximum smoothed CI_RedEdge (only if CI_RedEdge supplied)
  • Flowering duration — plateau width at ≥95% of peak NDVI
  • Peak NDVI, NDRE at heading, NDRE max

  1. Order & day axis — sort observations ascending; compute integer days from season start.
  2. Daily grid — np.interp the irregular observations onto a uniform daily grid so day-based smoothing and derivatives are well defined.
  3. Smoothing — Savitzky-Golay (window 11 days, polyorder 3); window auto-clamped to be odd and valid for short series.
  4. Markers — heading = argmax of smoothed NDVI; booting = argmax of smoothed CI_RedEdge; flowering duration = plateau width.
  5. Components — compute the four 0–1 terms; combine with (renormalized) weights.
  6. Classify & emit — map FSS to a band; print report; optionally write a one-row CSV.

4. Design Decisions & Trade-offs Considered

4.1 Residual-based roughness & stress (the key fix)

The first implementation measured CurveRoughness as the standard deviation of the raw day-to-day slope, and StressFlag as the raw NDVI drop relative to the peak value. Both produced false positives on a clean, synchronized field:

  • A well-synchronized field has a steep, fast rise — high slope variance, wrongly read as "jagged."
  • A narrow peak naturally has lower NDVI a few days out — wrongly read as a "stress drop."

The fix: measure both against the smoothed trend (residuals), not against raw slope or peak value. A legitimately steep, clean rise now scores ~0; only genuine noise/oscillation and anomalous dips raise the score.

# raw minus trend isolates noise/anomalies from legitimate growth
ndvi_s_at_obs = np.interp(days, grid, ndvi_s)
ndvi_residual = ndvi - ndvi_s_at_obs

# roughness = scatter about the trend in the run-up to heading
roughness_rmse = np.sqrt(np.mean(ndvi_residual[run_up] ** 2))

# stress = worst dip below the trend near heading
worst_dip = max(0.0, -np.min(ndvi_residual[near]))

4.2 Interpolate to a daily grid before smoothing

Savitzky-Golay assumes uniform spacing, but PlanetScope yields irregular clear-scene dates (~80 of 110 days). Smoothing on the raw observation index would distort day-based derivatives and the plateau-width measure. Linear interpolation onto a daily grid first makes "days ≥ 95% of peak" and the run-up window physically meaningful. Trade-off: interpolation across long cloud gaps is an approximation — acceptable for a coarse temporal score, and the residual measures still use the real observations.

4.3 Graceful degradation & weight renormalization

NDRE and CI_RedEdge are optional. If NDRE is absent, VigorAsymmetry is dropped and the remaining weights are renormalized to sum to 1, so the FSS stays on a 0–1 scale. If CI_RedEdge is absent, the booting-date marker is simply reported as None. This lets the same module run whether you supply 1 or 3 indices.

4.4 Why NDRE as the vigor reference, and why a 5-day ideal

No historical "expected healthy NDRE" exists in the inputs, so the season-max smoothed NDRE is used as the proxy ceiling — a self-referential but defensible baseline. The 5-day ideal flowering burst comes directly from the literature cited in the sync guide ("97% of florets open before noon in a concentrated 5-day burst"). Both are exposed as constants for later calibration against real seed-set data.

7.3 Run it (CLI)

python field_synchronization.py \
    --input your_field_summary.csv \
    --field-id MY_FIELD \
    --output field_synchronization.csv

--output is optional; omit it to only print the report. Exit code is 1 on input errors (missing column, too few rows, file not found).

7.4 Use as a library

import pandas as pd
from field_synchronization import compute_synchronization

df = pd.read_csv("your_field_summary.csv")
result = compute_synchronization(
    dates=df["date"], ndvi=df["NDVI_mean"].values,
    ndre=df["NDRE_mean"].values, field_id="MY_FIELD",
)
print(result.fss, result.classification)

7.5 Scaling to many fields

Loop over per-field CSVs (or a long table grouped by field id), call compute_synchronization per field, and concatenate the result rows into a multi-field field_synchronization.csv — one row per field, matching the pattern in the upstream field_phenology.csv.

8. Testing

8.1 Synthetic self-test (synchronized vs desynchronized)

Two Gaussian NDVI seasons (110 days, 80 random clear scenes) are generated: a sharp, clean peak (width 6, low noise) and a broad, jagged peak (width 22, high noise) with an injected dip during flowering.

import numpy as np, pandas as pd
import field_synchronization as fs

rng  = np.random.default_rng(0)
keep = np.sort(rng.choice(np.arange(0,110), 80, replace=False))
base = pd.Timestamp("2024-06-01")
dates = [base + pd.Timedelta(days=int(d)) for d in keep]

def curve(peak, width, noise):
    ndvi = 0.2 + 0.6*np.exp(-0.5*((keep-peak)/width)**2) + rng.normal(0,noise,keep.size)
    ndre = 0.15 + 0.45*np.exp(-0.5*((keep-peak)/width)**2)
    cire = 0.5 + 3.0*np.exp(-0.5*((keep-(peak-7))/width)**2)
    return ndvi, ndre, cire

n1,r1,c1 = curve(60, 6,  0.005)            # synchronized
n2,r2,c2 = curve(60, 22, 0.03)             # desynchronized
n2[(keep>58)&(keep<63)] -= 0.12           # sudden dip during flowering

fs._print_result(fs.compute_synchronization(pd.Series(dates), n1, r1, c1, field_id="SYNC"))
fs._print_result(fs.compute_synchronization(pd.Series(dates), n2, r2, c2, field_id="DESYNC"))

8.4 Suggested validation once real data arrives

  1. Run on a field with a known good seed-set season — confirm FSS < 0.10.
  2. Run on a field with a known poor season — confirm a worse band.
  3. Sanity-check the detected heading date against agronomist records (expect ±3–6 days).
  4. Once ≥1–2 seasons of paired seed-set outcomes exist, recalibrate the weights and band thresholds (or replace the hand-tuned weights with a fitted Random Forest / logistic model).
